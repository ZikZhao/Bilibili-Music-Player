# Windows 播放与搜索回归检查

从仓库根目录运行：

```powershell
dotnet run --project windows.Tests/PlaybackRegressionTests.csproj
dotnet build windows/bilibili-music-player-windows.csproj -p:Platform=x64
```

回归程序直接编译播放器使用的 `HttpRangeStream.cs`，通过模拟 HTTP 服务器验证读取字节、前后拖动、EOF、CDN 请求头、忽略 Range 的服务器、分段响应、取消加载、读取期间关闭、无效分段、提前断流和并发读取。无需测试框架、B 站账号或联网；任一检查失败时返回非零退出码。

`SearchSessionTests.cs` 直接编译应用使用的搜索会话，验证输入只获取候选词、提交时立即取消候选词、晚到响应不能覆盖新请求、分页隔离、加载中回退、预览换片只有一个历史条目、矩阵滚动位置恢复，以及跨页面保留预览。使用可控的异步响应，测试不依赖 B 站网络速度。

`ResidentTabsTests.cs` 验证顶层 tab 使用真正的实例驻留：反复往返只创建一次页面，隐藏不释放页面及其资源，重复选中当前 tab 不打断播放，关闭窗口时统一释放；一个页面清理失败也不能阻止其他页面释放。

界面验证请在 Visual Studio 部署并运行最新的 Windows 项目。仅执行 `dotnet build` 不会刷新之前部署到 `AppX` 目录的应用。搜索页的回退顺序为“预览 → 原矩阵结果 → 初始历史页”，窗体左上角、Alt+← 和 Esc 共用同一条历史。初始历史页及其他顶层 tab 的返回按钮禁用；此时 Esc 收起窗口并保留后台进程。窗口关闭按钮也收起窗口；托盘菜单的“退出”才释放资源并结束进程。

窗口生命周期检查：

1. 点击搜索历史条目，应直接显示搜索中的转圈状态，候选列表立即关闭。
2. 打开预览，按 Esc 应返回原矩阵结果，再按一次返回搜索历史；返回按钮此时禁用。
3. 再按 Esc 应收起窗口，进程仍存活。托盘单击或“显示窗口”应恢复原页面。
4. 收起后再次启动应用，应唤回同一窗口和进程，不出现第二个播放器；窗口可见时再次启动也只激活原窗口。
5. 预览中切到收藏，此时 Esc 应收起窗口，而不是修改隐藏搜索页的历史；恢复后切回搜索仍是暂停的原预览。
6. 托盘“退出”后，窗口、进程与托盘图标应全部消失；再次启动应正常显示初始收藏页。

顶层 tab 由 `MainWindow.PageHost` 常驻托管，不使用 `Frame.Navigate`。播放中切到收藏再返回，应当直接显示同一个播放器的暂停画面，保留进度、缓冲、音量与倍速，不出现重新获取视频的加载圈。加载过程中切走也应继续准备媒体，完成后保持暂停。只有离开预览状态、换片、播放失败或真正退出应用时才释放对应媒体。

还应检查候选词的鼠标选择、方向键选择、Enter 和放大镜提交、失败重试，以及窄窗口和明暗主题。候选文字应与原生编辑区域的左边缘对齐，窗口缩放、候选项回收及长查询横向滚动后也保持对齐；放大镜上鼠标应为普通箭头且无悬浮背景。搜索、收藏、设置的大标题前不应存在装饰竖线；侧栏选中指示条在明暗主题下都应为主题粉色。

`LibraryTests.cs` 验证动态链接、混排顺序、去重、循环与深度限制、文件夹解散、音源全局移除、账号隔离、离线文件、冲突备份、丢失提交响应及迟到请求。`AccountTests.cs` 使用模拟 HTTP 验证邮箱密码、确认邮件响应、恢复密码、刷新令牌竞态和跨账号请求拒绝，不操作实际邮箱。云端数据库回归位于 `supabase/tests/music_library.sql`，事务结束时回滚全部夹具。

收藏页操作使用独立 UI 夹具：`Inspect-Ui.ps1 -LibraryFixture sample -Tab favorites`，结束后 `-LibraryFixture restore`。注册、邮件确认和真实账号登录需要用户亲自验证，不应通过电脑控制工具输入用户凭证。
