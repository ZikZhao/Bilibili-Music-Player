# Windows 底部播放栏

本期实现共享音频播放及底部控制，不重新设计“正在播放”大页。

## 操作与布局

进度轨道沿整个底栏上边缘铺开，保留原生 Slider 的点击、拖动、键盘和辅助功能。轨道高 4 DIP，20 DIP 的输入区域跨在边缘两侧；拇指和有效轨道使用主题粉色。宽窗口的时间在按钮组左侧，窄窗口移到曲目详情下方。左侧详情占用剩余宽度并截断长标题，右侧依次为上一首、播放/暂停、下一首、静音、音量。

底栏拇指平时透明，仅在鼠标悬浮、按住拖动或键盘聚焦时显示。透明度不改变原生控件的布局、命中区域或辅助功能；进度轨道仍持续显示。派生 Slider 显式使用 WinUI 的 `DefaultSliderStyle`，避免回落到旧模板后导致轨道偏移和拇指尺寸变化。

底栏进度滑块只显示粉色核心，外圈背景和描边透明；轨道及粉色填充在悬浮、按下时保持原色。

宽窗口的时间使用 14 DIP 微软雅黑，窄窗口使用同一字体的 13 DIP。时间使用默认的 Full 行框及 `VerticalAlignment="Center"`，不裁剪行框，也不添加像素位移，作为用户评估外观的原始对齐基准。音量／静音均使用项目内的 IconPark 字体，两个字形共享完全一致的喇叭轮廓和字形间距。新增图标后运行 `windows/Tools/IconBuilder/build.mjs` 同步生成 `IconPark.ttf` 和 `Icons.xaml`；部署时字体及编译后的资源字典须同时更新。字体作为 Content 随构建输出和应用包分发。

已播放部分着色延伸至滑块中心。原生着色矩形继续作为定位滑块的布局占位，单独的着色层按实际滑块宽度延伸一半。原生交互容器向两侧各延伸半个滑块宽度，再裁剪到真实轨道宽度，使滑块中心从轨道起点移动到终点，两端均可裁掉半个滑块。着色没有零进度特判：起点自然为零，终点自然填满。底栏及正在播放页的音量悬浮标签将内部 0–1 音量四舍五入为 0–100 的整数。

没有音源或队列时播放按钮禁用；加入队列后可以从第一首开始。加载和缓冲有可见状态，失败保留曲目信息并允许原按钮重试。播放超过 3 秒时“上一首”先回到开头；否则选择队列上一首。手动下一首在单曲循环模式下仍然前进，自然结束才重复当前曲目；暂停时切歌保持暂停。静音恢复最近一次非零音量。

拖动过程中时间显示目标位置，播放器推送的位置不会夺回拇指；释放后提交一次跳转，取消则恢复真实位置。换歌会使旧拖动失效。来自 UI Automation 的范围值修改同样提交跳转，绑定更新不触发跳转。

## 播放链路

`AudioSourceResolver` 优先读取精确 BVID/CID 缓存，并只为首个 CID 兼容旧 BVID 缓存。未缓存时取得音频地址，交给 `AudioPlayerService` 使用携带 B 站请求头的 `HttpRangeStream` 边读边播，不再等待整段下载。缓存下载在后台进行，不阻塞首次播放；换歌、清空队列或进入视频预览会取消不再需要的准备和下载。

每次音源切换都有独立请求 ID、取消令牌和 Windows MediaPlayer/MediaSource/流资源。只有当前请求能够更新状态；旧请求、旧媒体事件、旧淡出和旧拖动均不能影响新歌。加载旧音源时就停止前一个音源，避免界面显示新歌却继续响旧歌。

MediaOpened 后才允许播放和跳转，播放状态取自真实媒体事件。原生 `PositionChanged` 和 `SeekCompleted` 事件即时推送位置，250 ms 的服务级位置循环补充刷新。部分流音源的 `BufferingProgress` getter 会返回 E_NOINTERFACE，由 C#/WinRT 转成 `InvalidCastException`；此前这个异常会让位置循环永久退出。现在删除未使用的缓冲百分比读取，缓冲状态只取 `PlaybackState`。原生状态读取期间的接口／对象释放异常仅跳过当前样本。源替换和退出统一释放媒体、随机访问流和 HTTP 流及事件订阅。用户可见状态经 UI SynchronizationContext 更新。

`IAudioPlaybackEngine`、`IAudioSourceResolver` 将原生媒体和网络适配器与播放会话分开。可移植回归直接编译生产 ViewModel；本机检查夹具另经真实 Windows MediaPlayer 验证解码和输入。Debug 夹具不修改收藏或登录状态，Release 不含夹具。

## 本次验证

2026-10-27：79 项回归、Debug/Release 编译通过。原生静音 WAV 验证了播放、暂停、下一首、UI Automation 跳到一半、实际鼠标拖动及 Home 键回到开头。430、620、1245 DIP 三种宽度的轨道对齐、控件顺序/边界和单份时间显示共 27 项测量检查通过，并检查明暗主题。

实际使用收藏中的 B 站音源验证播放、跳到 90% 位置、暂停恢复及列表循环；实际媒体时长 341.248 秒，未发生播放错误。测试结束清空了虚拟曲目，保留真实曲目在队列中，暂停在开头并恢复非零音量，收藏数据保持原样。

进度回归：`scripts/Test-PlaybackProgress.ps1` 使用真实 Windows MediaPlayer 和静音 WAV，检测实际播放位置、XAML Slider.Value、轨道填充宽度是否同时前进，并验证暂停、跳转恢复、换歌和切页后继续更新，确保自动更新没有反向触发 Seek。精确拖动预览另检查两种窗口宽度的 0%、25%、50%、75%、100%：滑块中心及可见着色终点按轨道全宽定位，两端对称裁剪半个滑块，不依赖解码器是否能停在 EOF。可用 `-OnlineBvid BV…` 对真实在线音源重复检查；每次 78 项检查。实际鼠标验证了四分之一、四分之三位置以及从裁剪后的半滑块开始拖动。底栏和正在播放页的音量标签均验证了 0.37 显示为整数 37。
