# Windows 底部播放栏

共享音频会话由底栏、正在播放页和播放列表页共同使用。

## 展开播放器

正在播放页覆盖整个右侧内容区（包括底栏），保留侧栏和自绘标题栏，没有大页面标题。
背景从当前封面创建有尺寸上限的 `LoadedImageSurface`，使用
Win2D/Windows Composition 的 40 DIP 高斯模糊及 Hard 边界处理，再叠加深色渐变以保证
文字对比度；前景封面与控件保持清晰。没有封面、解码失败或效果不可用时使用深色底。

侧栏可直接切页，窗口标题栏保留拖动和系统窗口按钮。返回按钮、Alt+← 和 Esc
先收起播放器并回到打开前的标签，音频不中断；顶级标签的 Esc 仍隐藏窗口到后台。
覆盖层与其他标签一样驻留，收起不会销毁页面和已加载的背景；隐藏时不跟随切歌重新解码，
再次展开才更新到当前封面。换封面时释放旧 surface 并拒绝迟到的加载回调，退出释放所有
composition 资源。新图形依赖为 `Microsoft.Graphics.Win2D` 1.4.0。

底栏的曲目详情按钮内边距为 8×6 DIP。悬浮或键盘聚焦时，16:9 缩略图叠加半透明黑色
遮罩和向上箭头；视觉层不参与布局、不拦截输入，也不在悬浮时改变内容位置。展开时重置
悬浮状态，返回底栏后不会残留箭头。

## 操作与布局

进度轨道沿整个底栏上边缘铺开，保留原生 Slider 的点击、拖动、键盘和辅助功能。轨道高 4 DIP，20 DIP 的输入区域跨在边缘两侧；拇指和有效轨道使用主题粉色。宽窗口的时间在按钮组左侧，窄窗口移到曲目详情下方。左侧详情占用剩余宽度并截断长标题，右侧依次为上一首、播放/暂停、下一首、静音、音量。

底栏拇指平时透明，仅在鼠标悬浮、按住拖动或键盘聚焦时显示。透明度不改变原生控件的布局、命中区域或辅助功能；进度轨道仍持续显示。派生 Slider 显式使用 WinUI 的 `DefaultSliderStyle`，避免回落到旧模板后导致轨道偏移和拇指尺寸变化。

底栏进度滑块只显示粉色核心，外圈背景和描边透明；轨道及粉色填充在悬浮、按下时保持原色。

宽窗口的时间使用 14 DIP Arial，窄窗口使用同一字体的 13 DIP，采用默认 Full 行框及 `VerticalAlignment="Center"`，无手动上移，保留 19 DIP 右间距。临时诊断边框已移除。音量／静音均使用项目内的 IconPark 字体，两个字形共享完全一致的喇叭轮廓和字形间距。新增图标后运行 `windows/Tools/IconBuilder/build.mjs` 同步生成 `IconPark.ttf` 和 `Icons.xaml`；部署时字体及编译后的资源字典须同时更新。字体作为 Content 随构建输出和应用包分发，并在构建时移除 svg2ttf 默认的额外行距。

已播放部分着色延伸至滑块中心。原生着色矩形继续作为定位滑块的布局占位，单独的着色层按实际滑块宽度延伸一半。原生交互容器向两侧各延伸半个滑块宽度，再裁剪到真实轨道宽度，使滑块中心从轨道起点移动到终点，两端均可裁掉半个滑块。着色没有零进度特判：起点自然为零，终点自然填满。底栏及正在播放页的音量悬浮标签将内部 0–1 音量四舍五入为 0–100 的整数。

没有音源或队列时播放按钮禁用；加入队列后可以从第一首开始。加载和缓冲有可见状态，失败保留曲目信息并允许原按钮重试。手动前后切歌在单曲循环模式下仍然有效，自然结束才重复当前曲目；暂停时切歌保持暂停。静音恢复最近一次非零音量。

## 单一播放列表

侧栏顶部为播放列表，正在播放入口移至底部、设置上方。表格依次显示序号、16:9 封面、曲目、UP 主、时长和移除操作；窄窗口将 UP 主合并到曲目下方。当前项始终是第一行，以 IconPark `music-rhythm` 音频柱形图代替序号；暂停时标记减淡。后续行从 1 开始编号。

`PlayerViewModel` 的只读可观察队列是唯一的播放顺序来源；每次加入都会创建独立的 `PlaybackQueueEntry`，同一视频的多个出现不会混淆。当前音源解析后的标题、CID、时长等元数据更新到对应队列项。

- 列表循环：自然结束或手动下一首，将当前项移到队尾，加载新的第一项。
- 上一首：无论已经播放多久，将队尾项移到最前并加载；不再先跳回当前曲目开头。
- 单曲循环：自然结束重播当前项，后续行减淡但仍可点击切换；手动前后切歌仍调整队列。
- 打乱：独立按钮，仅重新排列当前项之后的队列，不改变模式、当前音源、播放位置或暂停状态。
- 点击其他曲目：将所选项及其后的循环顺序转到最前，之前的项移到队尾；点击当前项只恢复播放。
- 下一首播放插入当前项之后并保持传入顺序；尾部入队追加到最后。移除当前项后播放下一项，保持原来的播放或暂停意图；清空则停止音频。

切换标签页不会创建另一份队列，也不会因打乱或修改播放模式重新加载音频。

## 视频缩略图

Windows 直接加载 B 站提供的封面 URL，现有缓存不做固定比例转换。实际收藏原图包含 3456×2160（16:10）和 1920×1080（16:9），不能依赖远端图片天然为某个比例。

搜索卡片、预览列表、收藏列表、底栏、正在播放页和播放列表页统一使用 `AspectRatioPanel` 的 16:9 容器，图片 `UniformToFill` 居中裁切，不拉伸；圆角由 `ImageBrush` 的 Border 背景处理。底栏封面为 80×45 DIP，列表封面为 64×36 DIP。图片原始比例不同也不改变行高或布局。

拖动过程中时间显示目标位置，播放器推送的位置不会夺回拇指；释放后提交一次跳转，取消则恢复真实位置。换歌会使旧拖动失效。来自 UI Automation 的范围值修改同样提交跳转，绑定更新不触发跳转。

## 播放链路

`AudioSourceResolver` 优先读取精确 BVID/CID 缓存，并只为首个 CID 兼容旧 BVID 缓存。未缓存时取得音频地址，交给 `AudioPlayerService` 使用携带 B 站请求头的 `HttpRangeStream` 边读边播，不再等待整段下载。缓存下载在后台进行，不阻塞首次播放；换歌、清空队列或进入视频预览会取消不再需要的准备和下载。

每次音源切换都有独立请求 ID、取消令牌和 Windows MediaPlayer/MediaSource/流资源。只有当前请求能够更新状态；旧请求、旧媒体事件、旧淡出和旧拖动均不能影响新歌。加载旧音源时就停止前一个音源，避免界面显示新歌却继续响旧歌。

MediaOpened 后才允许播放和跳转，播放状态取自真实媒体事件。原生 `PositionChanged` 和 `SeekCompleted` 事件即时推送位置，250 ms 的服务级位置循环补充刷新。部分流音源的 `BufferingProgress` getter 会返回 E_NOINTERFACE，由 C#/WinRT 转成 `InvalidCastException`；此前这个异常会让位置循环永久退出。现在删除未使用的缓冲百分比读取，缓冲状态只取 `PlaybackState`。原生状态读取期间的接口／对象释放异常仅跳过当前样本。源替换和退出统一释放媒体、随机访问流和 HTTP 流及事件订阅。用户可见状态经 UI SynchronizationContext 更新。

`IAudioPlaybackEngine`、`IAudioSourceResolver` 将原生媒体和网络适配器与播放会话分开。可移植回归直接编译生产 ViewModel；本机检查夹具另经真实 Windows MediaPlayer 验证解码和输入。Debug 夹具不修改收藏或登录状态，Release 不含夹具。
